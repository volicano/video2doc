# video2doc 安装与使用手册

> 把访谈、课程、教程类视频转成**带配图的单页 HTML 教程**。
> 输入一条 B 站 / YouTube 链接或本地视频文件，输出章节清晰、可跳回原片时间点的图文笔记。

本手册对应的版本：**0.1.0（M3）**。

## 1. 它能做什么

输入：

- B 站视频链接（`https://www.bilibili.com/video/BVxxxxxxx`，多 P 只处理第一 P）
- YouTube 视频链接（`https://www.youtube.com/watch?v=xxxx`）
- 本地视频文件（`D:\videos\lecture.mp4`）

输出（都在一个任务目录里）：

| 文件 | 说明 |
|---|---|
| `tutorial.html` | **最终产物**。单文件网页，CSS 和图片都内嵌，可直接发给别人 |
| `tutorial.md` | 同一份内容的 Markdown，图片用相对路径，方便继续编辑 |
| `preview.html` | 调试视图：抽帧曲线 + 每张图的 OCR 文字 + 对应口播 |
| `job.json` | 任务状态、配置快照、每阶段的指纹与耗时 |
| `stages/*.json` | 每一步的中间产物，可校验、可复用 |

一次 10 分钟左右的视频，产出大致是 5–8 节、3000–5000 字、20–30 张截图。

**它不做什么：**

- 不做自动发布，产出就是文件。
- 不做视频剪辑、翻译配音。
- 不替你判断内容对错；LLM 只被允许使用转写和 OCR 里的材料。

## 2. 工作原理

整条流水线是**确定性代码 + 三个 LLM 决策点**：

```
视频链接 / 本地文件
  ├─ ingest      下载、探测时长、收集字幕
  ├─ audio       抽 16kHz 单声道音轨
  ├─ transcript  优先用 CC 字幕，没有才跑语音识别
  ├─ correct     术语/错别字校正（可选，默认关）
  ├─ frames      场景检测 + 信息密度打分 + 去重
  ├─ ocr         只对选中的帧做文字识别
  ├─ align       镜头 ↔ 口播对齐
  ├─ segment     LLM 只回答「第几句开始新的一节、标题是什么」   ← LLM
  ├─ write       逐节写作，图片按编号引用                     ← LLM
  ├─ critique    确定性规则质检，可选 LLM 定向重写             ← LLM（可选）
  └─ render      单文件 HTML + Markdown
```

三个关键约束：

1. **时间戳永远由代码算**。LLM 看到的是带全局编号的句子，回答的也是句子编号，代码再换算成时间。模型编不出对不上的 `12:34`。
2. **一张图只归一节**。按时间重叠把画面分给重叠最多的章节，同一张截图不会在全文出现两次。
3. **每步都可缓存**。每个阶段有指纹（阶段名 + 版本 + 参数 + 源文件 + 上游指纹），指纹不变就秒过。

## 3. 环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| Python | 3.11 及以上 | 开发环境用的是 3.12 |
| ffmpeg | `ffmpeg` 和 `ffprobe` 都在 PATH | 抽音轨、抽帧 |
| 磁盘 | 每条视频 0.5–2 GB | 视频 + 音轨 + 帧 |
| 内存 | 8 GB 起 | 本地 ASR 建议 16 GB |
| GPU | 可选 | 有 NVIDIA 显卡时 ASR 快 5–10 倍 |
| LLM | 任意 OpenAI 兼容接口 | 没有也能跑前 7 步，只是不出教程 |

**不需要**的东西：不需要 Docker，不需要 PaddlePaddle，不需要 OpenCV，不需要数据库。

## 4. 安装

### 4.1 Windows（推荐路径）

```powershell
# 1) 装 Python 3.11+ 和 ffmpeg
winget install Python.Python.3.12
winget install Gyan.FFmpeg

# 2) 新建虚拟环境
cd D:\work\video2doc
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3) 装本体 + 本地语音识别 + 画面文字识别
pip install -e ".[local,ocr]"

# 4) 自检
v2doc doctor
```

`v2doc doctor` 会逐项检查 Python、ffmpeg、ffprobe、yt-dlp、ASR、OCR、LLM 密钥、输出目录、B 站/YouTube 连通性，并直接给出修复命令。

### 4.2 macOS / Linux

```bash
# macOS
brew install python@3.12 ffmpeg
# Debian / Ubuntu
sudo apt install python3.12 python3.12-venv ffmpeg

python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[local,ocr]"
v2doc doctor
```

### 4.3 按需选择安装组合

| 组合 | 命令 | 适用场景 |
|---|---|---|
| 最全（离线 ASR + OCR） | `pip install -e ".[local,ocr]"` | 推荐，本地免费 |
| 只用云端 ASR | `pip install -e "."` | 不想下 3 GB 模型 |
| 云端 ASR + 本地 OCR | `pip install -e ".[ocr]"` | 音量小、要画面文字 |
| 开发 | `pip install -e ".[local,ocr,dev]"` | 跑测试和 lint |

> 本地 ASR 依赖 `faster-whisper`，首次运行会从 HuggingFace 下载模型（`large-v3` 约 3 GB），只下一次。

### 4.4 配置模型密钥

```powershell
# DeepSeek（默认）
$env:DEEPSEEK_API_KEY = "sk-..."
```

想让设置永久生效（新开的终端也能用）：

```powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "sk-...", "User")
```

macOS / Linux 写进 `~/.bashrc` 或 `~/.zshrc`：

```bash
export DEEPSEEK_API_KEY="sk-..."
```

> 密钥只通过**环境变量名**引用，配置文件里从不写明文，`job.json` 里的配置快照也不含密钥。

## 5. 五分钟快速上手

```powershell
cd D:\work\video2doc
$env:PYTHONIOENCODING = "utf-8"   # Windows 控制台建议加上，避免中文乱码

# 1) 生成一份带注释的配置（可跳过，不生成也能跑）
v2doc init

# 2) 跑一条视频（会自动下载、转写、抽帧、写作、渲染）
v2doc run "https://www.bilibili.com/video/BV1XKJR6xE5e"

# 3) 打开生成的教程
v2doc open output/BV1XKJR6xE5e

# 4) 看转写文本
v2doc preview output/BV1XKJR6xE5e

# 5) 看抽帧和 OCR 选得对不对
v2doc frames output/BV1XKJR6xE5e --open
```

一次要跑很多条时：

```powershell
# urls.txt：一行一个链接，# 开头是注释
v2doc batch --file urls.txt --skip-done

# 看所有任务跑到哪了
v2doc status
```

任务目录名会自动从链接里取：

- B 站 → `BV1XKJR6xE5e`
- YouTube → 视频 ID
- 本地文件 → 文件名（去掉扩展名和非法字符）

想放到别处加 `-o`：`v2doc run "<链接>" -o D:\notes`。

跑完之后你应该看到：

```
✓ render        tutorial.html · 896 KB · 5 节
```

`tutorial.html` 双击就能看，也可以直接发给别人（图片已内嵌，单文件）。

## 6. 配置文件

### 6.1 位置与优先级

1. `v2doc run --config path\to\my.toml`（显式指定，最高优先级）
2. 当前目录下的 `video2doc.toml`
3. 当前目录下的 `v2doc.toml`
4. 都没有 → 全部使用内置默认值

> 配置文件按**当前工作目录**查找，不是按视频文件或任务目录查找。

### 6.2 最小可用配置

只写你想改的字段即可，其余走默认值：

```toml
[asr]
model = "large-v3"

[llm]
api_key_env = "DEEPSEEK_API_KEY"
```

### 6.3 常见配置模板

**A. 没有 NVIDIA 显卡（纯 CPU）**

```toml
[asr]
device = "cpu"
compute_type = "int8"
model = "medium"        # CPU 上 large-v3 比较慢，medium 够用
```

**B. 有显卡但没装 CUDA 运行库**

```toml
[asr]
device = "cpu"
compute_type = "int8"
model = "large-v3"
```

（想用 GPU 见 [13.3](#133-报错-library-cublas64_12dll-is-not-found)）

**C. 用云端语音识别**

```toml
[asr]
provider = "openai"
model = "whisper-1"
base_url = "https://api.openai.com/v1"
api_key_env = "OPENAI_API_KEY"
```

**D. 用本地大模型（Ollama / LM Studio / vLLM）**

```toml
[llm]
base_url = "http://127.0.0.1:11434/v1"
model = "qwen2.5:14b"
api_key_env = ""        # 空字符串 = 不发 Authorization 头
max_tokens = 4096       # 本地小模型按实际能力调小
```

**E. 只做转写和抽帧，不生成教程**

```toml
[write]
enabled = false
```

## 7. 完整配置参考

下面是全部字段与默认值。**未知字段会直接报错**（防止拼写手误悄悄失效）。

### 7.1 `[video]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `prefer_subtitles` | `true` | 有 CC 字幕时直接用，跳过 ASR |
| `max_duration_min` | `120` | 时长上限（分钟），防止误传直播回放 |
| `max_height` | `1080` | 下载分辨率上限 |
| `subtitle_langs` | `["zh-Hans","zh-CN","zh","zh-Hant","en"]` | 字幕语言优先级 |
| `cookies_from_browser` | `null` | 需要登录时填 `chrome` / `edge` / `firefox` |

### 7.2 `[asr]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `provider` | `"faster-whisper"` | `faster-whisper`（本地）或 `openai`（兼容 `/audio/transcriptions`） |
| `model` | `"large-v3"` | `tiny`/`base`/`small`/`medium`/`large-v3` |
| `language` | `"zh"` | 识别语言 |
| `hotwords` | `[]` | 手写热词，优先级最高 |
| `auto_hotwords` | `true` | 从标题/标签自动补充热词 |
| `initial_prompt` | `null` | 额外注入的领域背景 |
| `correct_with_llm` | `false` | 用 LLM 修术语/错别字（会把文本发到云端） |
| `glossary` | `[]` | 校正词表，留空复用 `hotwords` |
| `device` | `"auto"` | `auto` / `cuda` / `cpu` |
| `compute_type` | `"auto"` | `auto` / `float16` / `int8` / `int8_float16` |
| `vad` | `true` | 语音活动检测，跳过静音 |
| `beam_size` | `5` | 解码束宽，越大越准越慢 |
| `base_url` | `"https://api.openai.com/v1"` | 仅 `provider = "openai"` 时生效 |
| `api_key_env` | `"OPENAI_API_KEY"` | 云端 ASR 的密钥环境变量名 |
| `timeout_sec` | `900` | 云端 ASR 超时 |

### 7.3 `[llm]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `provider` | `"openai-compatible"` | 目前只有这一个适配器，覆盖所有兼容接口 |
| `base_url` | `"https://api.deepseek.com/v1"` | 接口地址 |
| `model` | `"deepseek-chat"` | 模型名 |
| `api_key_env` | `"DEEPSEEK_API_KEY"` | 密钥环境变量名；空字符串表示不需要鉴权 |
| `temperature` | `0.3` | 采样温度 |
| `max_tokens` | `8192` | 单次回答上限，被截断时调大 |
| `timeout_sec` | `300` | 单次请求超时 |

### 7.4 `[ocr]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `provider` | `"auto"` | `auto` / `rapidocr` / `none` |
| `language` | `"ch"` | 识别语言 |
| `min_confidence` | `0.5` | 低于该置信度的文字块丢弃 |

没装 OCR 依赖也不会失败，`align` 阶段只是少一维画面文字。

### 7.5 `[frames]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `strategy` | `"info-density"` | `uniform` 是均匀抽，用来对比 |
| `sample_interval_sec` | `0.0` | 0 = 按视频长度自动（短视频 1s，长视频 2–3s） |
| `analysis_width` | `320` | 分析用的缩略图宽度 |
| `max_frames` | `40` | 最多选多少张 |
| `min_gap_sec` | `8.0` | 两张图最小间隔，避免同一页 PPT 截三张 |
| `change_threshold` | `0.10` | 相邻帧差异超过它算换镜头 |
| `hash_threshold` | `12` | 感知哈希阈值，补刀白底 PPT 翻页 |
| `min_shot_score` | `0.04` | 低于它基本是纯人脸口播，不选 |
| `coverage_buckets` | `8` | 时间轴分几段保证覆盖 |

### 7.6 `[write]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉则只保留文本/图片/对齐数据 |
| `language` | `"auto"` | `auto` / `zh` / `en` |
| `max_sections` | `12` | 超出时合并相邻最短的两节 |
| `min_section_sec` | `60.0` | 太短的段不单独成节 |
| `max_section_sec` | `600.0` | 单节超过 10 分钟，按停顿再切一刀 |
| `chunk_utterances` | `260` | 分段时每次喂给 LLM 的句子数 |
| `chunk_overlap` | `20` | 分块之间的重叠句数 |
| `max_images_per_section` | `4` | 单节最多几张图 |
| `max_section_chars` | `6000` | 单节转写截断长度 |
| `temperature` | `0.4` | 写作温度 |
| `review` | `false` | 质检严重问题时让 LLM 定向重写（额外花费） |
| `max_rewrites` | `3` | 最多重写几节 |

### 7.7 `[render]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `format` | `"html-single"` | 单文件 HTML |
| `theme` | `"light"` | `light` / `dark` |
| `embed_images` | `true` | 图片 base64 内嵌 |
| `debug_html` | `true` | 生成 `preview.html` 调试图 |
| `title` | `null` | 自定义教程标题，留空用 LLM 生成的标题 |
| `show_toc` | `true` | 显示目录 |
| `image_captions` | `false` | 图注显示 OCR 画面文字（录屏类视频噪声大） |

### 7.8 `[network]`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `proxy` | `null` | 例如 `"http://127.0.0.1:7890"` |

## 8. 选择模型与服务

### 8.1 LLM

只要兼容 `POST /chat/completions` 且支持 `response_format: json_object` 即可。

| 服务 | `base_url` | `model` 示例 | `api_key_env` |
|---|---|---|---|
| DeepSeek（默认） | `https://api.deepseek.com/v1` | `deepseek-chat` | `DEEPSEEK_API_KEY` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | `DASHSCOPE_API_KEY` |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` | `MOONSHOT_API_KEY` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` | `ZHIPU_API_KEY` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | `OPENAI_API_KEY` |
| Ollama（本地） | `http://127.0.0.1:11434/v1` | `qwen2.5:14b` | `""` |
| LM Studio（本地） | `http://127.0.0.1:1234/v1` | 你加载的模型名 | `""` |

> 模型选择直接影响成稿质量：一次 30–60 分钟的视频大约 8–15 次调用，建议至少用 32k 上下文的模型。

### 8.2 ASR

| 方案 | 优点 | 缺点 |
|---|---|---|
| `faster-whisper` + `large-v3`（默认） | 离线、免费、中文质量好 | 首次下 3 GB 模型；CPU 上慢 |
| `faster-whisper` + `medium` | CPU 上快 2–3 倍 | 术语错误更多 |
| 云端 `openai` 兼容接口 | 不占本地算力 | 要钱、要上传音频；部分服务不回时间戳 |

> **时间戳很重要**：图文对齐靠它。如果云端服务只返回纯文本，`align` 会退化，日志里会提示。

### 8.3 热词：性价比最高的一个开关

中文技术内容里，缩写和英文标识符是 ASR 的重灾区。把它们塞进 `hotwords` 几乎零成本：

```toml
[asr]
hotwords = ["Obsidian", "QuickAdd", "闭包", "垃圾回收", "时间复杂度", "AQS", "CAS"]
```

`auto_hotwords = true` 时还会从视频标题和标签里自动补充。小模型（`tiny`/`small`）+ 技术内容，不开热词基本不能用。

## 9. 命令参考

### 9.1 `v2doc run`

处理一条视频。

```bash
v2doc run <链接或文件> [选项]
```

| 选项 | 说明 |
|---|---|
| `-o, --out PATH` | 输出根目录，默认 `output` |
| `--job-dir PATH` | 直接指定任务目录（忽略 `--out`） |
| `-c, --config PATH` | 指定配置文件 |
| `--from STAGE` | 从某阶段开始**强制重跑**（含之后所有阶段） |
| `--force` | 忽略所有缓存 |

### 9.2 `v2doc batch`

批量处理多条视频。**串行执行**，单条失败不影响其他。

```bash
v2doc batch "https://www.bilibili.com/video/BV1xx" "https://www.bilibili.com/video/BV2xx"
v2doc batch --file urls.txt --skip-done
v2doc batch --file urls.txt --stop-on-error
```

`urls.txt` 一行一个，`#` 开头或行尾都是注释，空行和重复项会自动去掉。

| 选项 | 说明 |
|---|---|
| `-f, --file PATH` | 从文件读链接 |
| `-o, --out PATH` | 输出根目录，默认 `output` |
| `-c, --config PATH` | 配置文件 |
| `--skip-done` | 已有 `tutorial.html` 的任务直接跳过 |
| `--stop-on-error` | 遇到失败立刻停下（默认继续跑后面的） |
| `--from STAGE` | 对每个任务强制从该阶段重跑 |
| `--force` | 对每个任务全量重跑 |

跑完会打印汇总表：成功 / 跳过 / 失败 + 失败原因 + LLM 合计用量。有失败时退出码为 `1`，方便脚本判断。

### 9.3 `v2doc status`

查看输出目录里所有任务的状态。

```bash
v2doc status                    # 默认看 output/
v2doc status D:\notes --failed  # 只看有失败阶段的
v2doc status --json             # 输出 JSON，便于脚本处理
```

显示：任务 ID、进度（`完成` / `✗ 阶段名` / `7/11`）、标题、累计耗时、教程大小、更新时间。

### 9.4 `v2doc rewrite`

只重写某一节，其余章节保持原样。改完之后会自动重跑质检和渲染。

```bash
v2doc rewrite output/BV1XKJR6xE5e --section 4
v2doc rewrite output/BV1XKJR6xE5e --section 4 --hint "这节讲的是任务接管和中断，标题别写成 Profile 隔离"
v2doc rewrite output/BV1XKJR6xE5e -s 2 --config my.toml
```

| 选项 | 说明 |
|---|---|
| `-s, --section N` | 章节号，从 `1` 开始（和 HTML 里显示的一致，必填） |
| `--hint TEXT` | 额外写作要求，会追加在提示词里，优先级高于通用规则 |
| `-c, --config PATH` | 配置文件 |

- 只调用一次模型（这一节），不会重写导语和其他章节
- 模型会顺便给这一节一个新标题；不合适可以在校对界面或 `overrides.json` 里再改
- 会清掉这一节在 `overrides.json` 里的旧覆盖（其他章节的修改保留），否则渲染时旧内容会盖住新稿
- 章节号写错时会列出可选范围，例如「可选章节：1, 2, 3, 4, 5」
- 花掉的 token 照常记进 `job.json` 的 `usage`

> 适合「内容没错但写法不满意」的局部返工。如果整篇风格都不对，直接 `v2doc resume <任务目录> --from write` 更省事。

### 9.5 `v2doc render`

应用 `overrides.json` 重新生成 `tutorial.html` 和 `tutorial.md`。**不调用模型，不需要 API Key，通常两秒内完成。**

```bash
v2doc render output/BV1XKJR6xE5e
```

它会重新跑 `render` 阶段（以及它依赖的检查），但上游产物一个都不动：

- `stages/write.json` 不会被改写
- 覆盖层的内容参与 `render` 的指纹，改了 `overrides.json` 就会重渲染
- 想同时用另一份配置（比如换 `render.embed_images`）就加 `-c`

### 9.6 `v2doc review`

在浏览器里校对成稿：左边章节、中间正文、右边配图，改完点「保存并渲染」，直接写 `overrides.json` 并重新生成 HTML。**不调用模型（除非你主动点「AI 重写本节」），不需要联网。**

```bash
v2doc review output/BV1XKJR6xE5e
v2doc review output/BV1XKJR6xE5e --no-open   # 只打印地址，不自动开浏览器
v2doc review output/BV1XKJR6xE5e -p 8765     # 固定端口
```

| 选项 | 说明 |
|---|---|
| `-p, --port N` | 监听端口，默认 `0` 表示随机分配；只监听 `127.0.0.1` |
| `--no-open` | 不自动打开浏览器 |
| `-c, --config PATH` | 配置文件，渲染参数和 `v2doc render` 保持一致 |

启动后终端会打印带令牌的地址，例如 `http://127.0.0.1:54321/?token=...`。令牌只用来防止本机其他程序乱调接口，每次启动都会变。

界面里能做的事：

- 改教程标题、导语、每一节的标题和正文（Markdown）
- 看本节配图：`插入` 在光标处写 `[[img:N]]`，`↑` / `↓` 调顺序，`✕` 移出本节
- 从「其他章节借用画面」把图挪到本节（原章节会自动去重）
- 勾选「预览」看渲染后的效果，图片、时间戳和成品一致
- `Ctrl+S` 保存并渲染；有未保存修改时关页面会提醒
- 「AI 重写本节」调用一次模型（需要 API Key），会清掉这一节已有的人工修改

保存规则和手写 `overrides.json` 完全一样：只写和模型原稿不同的字段，全部改回原样时文件会被删掉。所以随时可以 `v2doc render`，或者直接编辑 `overrides.json` 接手。

几点注意：

- `[[img:N]]` 的编号跟着**本节图片顺序**走。调整顺序后，正文里的编号会指向别的图，保存前留意一下
- 服务只监听 `127.0.0.1`，`Ctrl+C` 结束；终端关掉页面就打不开了
- 每次保存都会完整重新渲染（通常 2–3 秒），不会写坏文件

## 10. 产物说明

```
output/BV1XKJR6xE5e/
├─ tutorial.html      # 最终产物（单文件，图片内嵌）
├─ tutorial.md        # Markdown 版本（图片相对路径）
├─ preview.html       # 抽帧 / OCR / 对齐调试视图
├─ job.json           # 任务状态 + 配置快照 + 每步指纹
├─ overrides.json     # 人工覆盖层（可选，流水线不写）
├─ media/             # 原视频、音轨、字幕
├─ frames/            # 选中的画面（jpg）
└─ stages/
   ├─ ingest.json     # 视频元信息、字幕来源
   ├─ audio.json      # 音轨路径、采样率
   ├─ transcript.json # 带时间戳的句子
   ├─ frames.json     # 选帧结果 + 信息密度曲线
   ├─ ocr.json        # 每张图的文字块（含坐标和置信度）
   ├─ align.json      # 每张图 ↔ 这段口播
   ├─ segment.json    # 章节边界（句子编号 + 标题）—— 注意不是时间
   ├─ write.json      # 每节 Markdown + 配图映射
   ├─ critique.json   # 质检结果
   └─ render.json     # 产物路径与大小
```

`job.json` 里的 `stages` 记录了每个阶段的 `status`（`done` / `skipped` / `failed`）、`elapsed`、`summary`、`fingerprint` 和产物路径；`usage` 记录这个任务累计的 LLM 调用次数与 token 用量（输入 / 输出分开记）。

**为什么 `segment.json` 存句子编号而不是秒数？** 因为这是防止模型编时间戳的核心手段：边界永远由编号换算，语音识别的 ±0.5s 误差也不会被放大。

## 11. 缓存与断点续跑

### 11.1 指纹规则

每个阶段的指纹 = `hash(阶段名 + 版本 + 参数 + 源文件大小/mtime + 上游指纹)`。

因此：

| 你改了什么 | 会重跑什么 |
|---|---|
| 什么都没改 | 什么都不跑（秒过） |
| `asr.model` | `transcript` 及之后 |
| `llm.model` / `max_tokens` | `segment` 及之后（如果分段参数里包含 llm 配置） |
| `write.*` | `segment` 及之后 |
| `render.*` | `render` |
| `overrides.json` | 只重跑 `render`（不调用模型） |
| 换了视频文件 | 全部 |

### 11.2 `--from` 与 `--force`

- `--from write`：强制重跑 `write`，以及它下游的 `critique`、`render`。上游命中缓存。
- `--force`：全部重跑（会重新下载视频！）。

常用组合：

```bash
# 只重写正文（改了提示词 / 换了模型）
v2doc resume output/BV1XKJR6xE5e --from write -c my.toml

# 只重新抽帧和 OCR（改了 frames 参数）
v2doc resume output/BV1XKJR6xE5e --from frames

# 只重新渲染（改了主题 / 标题 / overrides.json）
v2doc render output/BV1XKJR6xE5e

# 重新转写（换了 ASR 模型 / 设备）
v2doc resume output/BV1XKJR6xE5e --from transcript
```

阶段顺序（`--from` 的合法取值）：

```
ingest → audio → transcript → correct → frames → ocr → align → segment → write → critique → render
```

### 11.3 中断了怎么办

`Ctrl+C` 之后重跑**同一条命令**即可，已完成的阶段全部命中缓存：

```bash
v2doc resume output/BV1XKJR6xE5e
```

## 12. 质量调优

### 12.1 章节分得太碎 / 太粗

```toml
[write]
min_section_sec = 90    # 太碎的段落并入相邻节
max_sections = 8        # 合并到 8 节以内
max_section_sec = 600   # 单节最长 10 分钟
```

### 12.2 配图太少

```toml
[write]
max_images_per_section = 6   # 默认 4
```

同时可以放宽抽帧：

```toml
[frames]
max_frames = 60
min_gap_sec = 6
min_shot_score = 0.03
```

### 12.3 该有图的地方没图

先打开 `preview.html` 看抽帧质量：

```bash
v2doc frames output/BV1XKJR6xE5e --open
```

如果是纯人脸口播被过滤掉了，调低 `min_shot_score`；如果是同一页 PPT 只留了一张，说明 `min_gap_sec` 生效了，这通常是想要的效果。

### 12.4 术语错得离谱

1. 换 `large-v3`
2. 加 `hotwords`
3. 开 `correct_with_llm = true` 并给 `glossary`

```toml
[asr]
correct_with_llm = true
glossary = ["Obsidian", "QuickAdd", "闭包", "词法环境"]
```

校正只会接受长度变化在 0.5–1.6 倍之间的修改，防止模型自由发挥；时间戳不动。

> 开启后字幕文本会发给 LLM 服务商，介意隐私就保持关闭。

### 12.5 正文太短 / 太水

- 换更强的模型（写作质量几乎完全由模型决定）
- 降低 `min_shot_score` 不一定有用，重点是**材料密度**：口播本身信息少，写不出花来
- 不要盲目提高 `temperature`，结构会散

### 12.6 教程标题不好看

LLM 会根据章节标题起一个教程标题（≤ 24 字）。想强制指定：

```toml
[render]
title = "我的 Obsidian 自动化笔记系统"
```

### 12.7 质检提示太多

`critique` 的提示分三档：`low` 只是建议，`medium`/`high` 才值得处理。想让它真的动手改：

```toml
[write]
review = true
max_rewrites = 3
```

注意：这会额外调用 LLM，且重写后长度明显缩水时会保留原稿。

### 12.8 手工修改成稿（`overrides.json`）

模型写出来的东西大体对、局部不对时，不用整篇重跑。在任务目录里建一个 `overrides.json`，渲染时按它覆盖：

```json
{
  "title": "Obsidian 8 个插件：从 0 到 1 的笔记系统",
  "intro": "这份教程适合刚接触 Obsidian 的人……",
  "sections": {
    "4": {
      "title": "任务接管、中断与终止",
      "markdown": "这一节讲三件事……\n\n[[img:1]]\n\n……",
      "images": ["frames/f17_00218s.jpg", "frames/f19_00249s.jpg"]
    }
  }
}
```

| 字段 | 作用 |
|---|---|
| `title` | 教程标题（会被 `render.title` 覆盖，如果你配了的话） |
| `intro` | 导语，写 `""` 表示清空 |
| `sections` | 以章节号为键（从 `1` 开始），只写要改的节 |
| `sections.N.title` | 这一节的标题 |
| `sections.N.markdown` | 这一节的正文，图片用 `[[img:N]]` 占位 |
| `sections.N.images` | 这一节的图片顺序；只写文件名（`f17_...jpg`）也行 |

改完执行：

```bash
v2doc render output/BV1XKJR6xE5e
```

**规则和边界：**

- `overrides.json` 属于你，流水线永远不写它，`--force` 也不会删
- 只影响 `render`：`stages/write.json` 一个字节都不动；改了覆盖层只会重渲染，不会重跑模型
- `images` 里写的图必须在 `write.json` 里出现过（也就是之前选中的画面）。想把别的帧加进来，先跑 `v2doc frames` 看看有哪些
- 图片被某节「认领」后，原来那节会自动去掉它，避免同一张截图出现两次
- 未知文件名、越界的 `[[img:N]]`、不存在的章节号都会在渲染时打印提醒，不会静默出错
- 文件可以用记事本保存（带 BOM 也能读），格式错了会直接报错并指出位置

> 这套覆盖层就是 `v2doc review` 校对界面的数据格式。不想手写 JSON 的话，直接运行 `v2doc review <任务目录>`，界面保存时写的就是这个文件。

## 13. 常见问题排查

### 13.1 模型下载卡住 / 报 401、CAS Client Error

HuggingFace 的 xet 加速在部分网络下会失败，关掉或换镜像：

```powershell
$env:HF_HUB_DISABLE_XET = "1"
$env:HF_ENDPOINT = "https://hf-mirror.com"
```

模型会缓存在 `%USERPROFILE%\.cache\huggingface`（Linux/macOS 是 `~/.cache/huggingface`），只下一次。

### 13.2 B 站视频下载失败（412 / 需要登录）

用浏览器的登录态：

```toml
[video]
cookies_from_browser = "chrome"   # 或 edge / firefox
```

另外先把 yt-dlp 升到最新：

```bash
pip install -U yt-dlp
```

### 13.3 报错 `Library cublas64_12.dll is not found`

有 NVIDIA 显卡，但没装 CUDA 12 的运行库。两个选择：

**A. 直接用 CPU（推荐先跑通）**

```toml
[asr]
device = "cpu"
compute_type = "int8"
model = "medium"
```

**B. 补上运行库**

```powershell
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12
$nv = ".venv\Lib\site-packages\nvidia"
$env:PATH = "$PWD\$nv\cublas\bin;$PWD\$nv\cudnn\bin;$env:PATH"
```

然后再把 `device` / `compute_type` 改回 `auto`。

> RTX 50 系（Blackwell, sm_120）需要较新的 CTranslate2，未必被当前版本支持。报 CUDA capability 相关错误时，只能等上游更新或继续用 CPU。

### 13.4 报错「LLM 返回的不是合法 JSON」

最常见的原因是**输出被 `max_tokens` 截断**（尤其是某一节转写特别长时）。按顺序试：

1. 调大输出上限

```toml
[llm]
max_tokens = 8192
```

2. 减小单节材料量

```toml
[write]
max_section_chars = 4000
max_section_sec = 480
```

3. 换上下文更大的模型

### 13.5 YouTube 连不上

```toml
[network]
proxy = "http://127.0.0.1:7890"
```

### 13.6 OCR 没跑

```bash
pip install "video2doc[ocr]"
v2doc providers     # 看 OCR 是否可用
```

没装也不影响出教程，只是画面里提取不到文字，配图说明会少一维。

### 13.7 控制台中文乱码

Windows 老控制台默认 GBK：

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

程序本身已经会尝试把 stdout 切成 UTF-8，但外层终端如果仍按 GBK 解码，看起来还是会花。换成 Windows Terminal 或 PowerShell 7 更稳。

### 13.8 没有 API Key 还能跑吗

能。`segment` / `write` / `critique` / `render` 会**跳过并说明原因**，前面的下载、转写、抽帧、OCR、对齐产物全部保留：

```
– write        跳过：未配置 DEEPSEEK_API_KEY
```

后续补上密钥再跑同一条命令就会继续。

### 13.9 同一个视频跑两遍结果不一样

说明两次命中了不同的缓存路径（比如改了配置或换了模型）。看 `job.json` 里的 `fingerprint`，或直接 `--force` 全量重跑。

LLM 本身有随机性（`temperature = 0.3/0.4`），即使输入完全相同，文字也会有差异，这是正常的。

### 13.10 想全部重来

```bash
v2doc run "<链接>" --force        # 重新下载 + 重跑
# 或者直接删任务目录
rmdir /s /q output\BV1XKJR6xE5e
```

## 14. 性能与成本

### 14.1 实测耗时（CPU）

参考机器：28 线程 CPU，`large-v3` + `int8`，6–10 分钟的视频：

| 阶段 | 6.4 分钟视频 | 9.9 分钟视频 |
|---|---|---|
| 下载 + 抽音轨 | 4 s | 6 s |
| 语音识别（CPU） | 264 s | 352 s |
| 抽帧 | 7 s | 11 s |
| OCR（26–40 张） | 72 s | 122 s |
| 对齐 + 分段 | 2 s | 5 s |
| 写作（LLM） | 19 s | 27 s |
| 渲染 | 2 s | 2 s |
| **合计** | **≈ 6 分钟** | **≈ 9 分钟** |

有可用的 GPU 时，语音识别通常能压到 1/5–1/10。

### 14.2 LLM 成本

一条 30–60 分钟的视频大约 8–15 次调用。按 DeepSeek 的量级估算，单条成本通常在**几毛钱**（具体价格随官方调整）。想省钱：

- 关掉 `review`
- `max_sections` 调小（节数越少调用越少）
- 用 `--from` 只重跑出问题的那部分

实际用量会记在 `job.json` 的 `usage` 里，`v2doc run` 结束时的汇总面板和 `v2doc batch` 的结尾都会显示「N 次 · 输入 X / 输出 Y tokens」，拿它乘服务商单价就能估成本。

### 14.3 磁盘

| 内容 | 大小（10 分钟视频） |
|---|---|
| 视频 + 音轨 | 100–500 MB |
| 帧（40 张 jpg） | 5–15 MB |
| 产物 + 中间 JSON | 1–2 MB |

`tutorial.html` 因为内嵌图片会到 1 MB 左右；不需要就设 `embed_images = false`。

## 15. 隐私与合规

**默认会联网的部分：**

- 下载视频（B 站 / YouTube）
- `transcript` 阶段下载 Whisper 模型（只第一次）
- `llm` 阶段把**转写文本和 OCR 文字**发给你配置的 LLM 服务商

**不会发出去的：**

- 视频文件本身
- 画面截图（图片只在本机，HTML 里的 base64 也不上传）

**完全离线的组合：**

```toml
[asr]
provider = "faster-whisper"

[write]
enabled = false
```

这样就只有下载视频这一步需要网络。

本项目仅用于个人学习与内容整理，不存储、不二次分发原始视频。请遵守 B 站 / YouTube 的服务条款与版权规定；用别人的视频做二次创作前请确认授权。

```bash
pip install -e ".[local,ocr,dev]"
pytest            # 113 个测试
ruff check src tests
```

项目结构：

```
src/video2doc/
├─ cli.py             # 命令行
├─ config.py          # 配置模型 + 示例配置
├─ doctor.py          # 环境自检
├─ pipeline.py        # 阶段调度 + 指纹缓存
├─ job.py             # 任务目录与 job.json
├─ schema.py          # 所有阶段产物的 pydantic 模型
├─ stages/            # 11 个阶段，一阶段一文件
├─ providers/
│  ├─ asr/            # faster-whisper / openai 兼容
│  ├─ ocr/            # rapidocr / none
│  └─ llm/            # openai 兼容
├─ writing/           # 分段、写作、质检、提示词
├─ render/            # HTML / Markdown 渲染
└─ utils/             # ffmpeg、文本、Markdown 工具
```

**加一个 ASR / OCR / LLM provider**：在对应 `providers/*/` 下写一个类，继承基类并加 `@register`，然后 `v2doc providers` 就能看到它。不需要改流水线。

**加一个阶段**：在 `stages/` 写一个 `Stage` 子类，`params()` 返回参与指纹的参数，然后加进 `stages/__init__.py:default_stages()`。

## 17. 已知限制

- 只处理多 P 视频的第一 P（会在日志里提示）。
- 画质低于 720p 时，代码类画面的 OCR 明显下降。
- OCR 会把代码符号认错（例如 `outer()` → `outer0`）。写作提示词要求给代码块加注「代码为画面识别结果，符号可能有误」，但发布前请对照原片核对代码。
- 写作质量取决于所用模型；本地小模型能跑通，但结构和文字明显不如云端大模型。
- 本地视频的标题就是文件名，可以用 `[render] title` 覆盖。
- 语音识别时间戳有 ±0.5 s 误差，对齐时留了缓冲。
- 横屏、有稳定 PPT / 代码画面的教学视频效果最好；全程人脸口播只能拿到口播文字。
- 录屏类视频的 OCR 会混入浏览器界面文字，因此图注默认关闭。
- 没有自动发布能力。
