# 发布流程

发布使用 PyPI 的 [trusted publishing](https://docs.pypi.org/trusted-publishers/)：GitHub Actions 通过 OIDC 直接上传，仓库和本机都不保存 API token。

## 一次性配置

在 PyPI 上给项目添加 trusted publisher：

1. 登录 PyPI，打开 <https://pypi.org/manage/project/video2doc/settings/publishing/>
2. 选择 **GitHub**
3. 填写：

   | 字段 | 值 |
   |---|---|
   | Owner | `volicano` |
   | Repository name | `video2doc` |
   | Workflow name | `publish.yml` |
   | Environment name | 留空 |

4. 保存后，这个 workflow 才能拿到上传权限

`Environment name` 必须留空，因为 `.github/workflows/publish.yml` 里没有设置 `environment`；如果以后想加人工审批，再在 workflow 和 PyPI 两边同时填同一个名字。

## 发版步骤

1. 改版本号，两处保持一致：
   - `pyproject.toml` 的 `[project].version`
   - `src/video2doc/__init__.py` 的 `__version__`
2. 更新 `CHANGELOG.md`：把 `[Unreleased]` 改成 `[X.Y.Z] - YYYY-MM-DD`
3. 本地验证：

   ```bash
   uv build
   pytest
   ruff check .
   ruff format --check .
   ```

4. 提交并推送 `main`：

   ```bash
   git add -A
   git commit -m "chore(release): X.Y.Z"
   git push
   ```

5. 打 tag 并推送（这一步才会触发发布）：

   ```bash
   git tag -a vX.Y.Z -m "video2doc vX.Y.Z"
   git push origin vX.Y.Z
   ```

6. 打开 <https://github.com/volicano/video2doc/actions/workflows/publish.yml> 看流水线：`Test → Build → Publish to PyPI`
7. 发布成功后确认 <https://pypi.org/project/video2doc/>，再按需在 GitHub 上建 Release

## 注意

- workflow 只在推送 `v*` tag 时触发，普通 `main` 提交不会发布
- tag 名必须等于 `v` + `pyproject.toml` 里的版本号，否则 `Build` job 会直接失败
- PyPI 不允许覆盖已发布的版本，上传失败需要修复后换一个新的版本号
- 不需要删除或轮换任何 token；本机也不再需要 `~/.pypi-token`
